# 統一キャラクター工房 · v0.24

[繁體中文](CHARACTER_ATELIER.zh-TW.md) · [简体中文](CHARACTER_ATELIER.zh-CN.md) · **日本語** · [English](CHARACTER_ATELIER.en.md)

名前、成人年齢／性別、一つの人物プロンプト、任意LoRA、トリガー、Seed、外見、性格、目標、任意背景、手動AI下書き、カードを一画面で扱います。保存は本人の設定を検証／確定し、同じ外見識別情報／衣装のスナップショットで立ち絵差分／歩行画像とCG一枚を予約します。一致する完成素材は自動適用し、部品の履歴から復元できます。この明示保存フローに別の適用ボタンは不要です。

プロンプトだけでも生成できます。`<lora:filename:0.8>` は選択環境内の唯一の同名資源を解決し、一つ目が人物、二つ目が衣装、最大二つです。正規化した外見識別情報を人物設定とSDバインドに保存します。他人、ローカルSD、ネイティブテンプレート、人間プレイヤーを保持し、モデルを推測／ダウンロードしません。

ネイティブSDは独立した埋め込み画面で、未保存フォームを取得しません。元PNG／PNG Info／完全API payloadを読み込み、テンプレートを保存して用途を選びます。PNGは記録済み情報だけで、未記録拡張には完全payloadが必要です。統一フローはコピー要求のWebUI ADetailer正向外見識別情報／表情を置換し、検出器、マスク、ネガティブ等を保持します。元テンプレートとネイティブ画面は変えません。LoRAノードを持つネイティブComfyUIにはLoRA指定が必要で、プロンプトだけなら対応内蔵フローを使えます。品質はモデルとテンプレートに依存します。

## 保護されたローカルAPI

POST `/api/art` は `X-Play-Token`、既存Host／Origin確認、`operation: "atelier"` を要求します。

- `params.command: "state"`：SD設定、人物ごとの現状態／テンプレート指紋、最新生成パック。
- `save_character`：正確な欄は `command, actor, mode, profile, before, sd, binding_before, scene, description`。成人schemaを使い、`before` と `binding_before` で他ページによる過期編集を拒否します。現人物保存はイベント前置、財布、在庫、関係、他人を保持します。テンプレートは将来の人物だけを変え、旧世界を生成しません。
- `build_saved_character`：`command, actor`。新セーブ後の確定済みpromptで美術だけを予約し、人物イベントを書きません。
- `retry_character`／`cancel_character`：`command, actor, id`。IDは本人の現パックと一致する必要があります。再試行は完成結果を保持し、満キューは待って自動再開します。
- 既存 `binding`、`generate`、`apply`、`restore` は保持します。restoreは本人の自動適用待ちを取り消してファイルを残します。

無視対象の `work/character-pipelines.json` に保存します。一パックは二仕事と適用済み段階を持ちます。背景処理は人物／バインド／衣装指紋を照合し、新保存が旧計画を置換します。変更した人物／衣装は失効し、黙って適用しません。取消は所有仕事だけに作用し、再起動中断は再試行可能です。同じ美術配合なら名前だけの変更も結果を再利用できます。

プレイヤーは人間操作です。背景は私的作者文字で過去イベントを作りません。CG選択は移動や経験記憶を発生させません。美術、保存、ロードでAPI枠をリセットせず、人物美術処理は課金LLMを呼びません。

## 保持する人物ツール

成人年齢18–120、唯一の名前32文字以内、口調／性格500、目標100、背景2000、プロンプト1000文字です。`look` は八髪型、髪／肌／目色、柔和／楕円／角形顔、身長150–205、細身／一般／運動／豊満体型、初期衣装色です。任意の標準ピクセル制御とSD記述であり、3D造形ではありません。購入衣装は実際の配合を使います。

手動AI下書きは本人だけで既存上限を使い、オフライン例を明示します。カードはUTF-8 `lifebox.character.v1` JSON、画面上限64KiBで、人物設定だけを持ち、画像、モデル、キー、記憶を含みません。旧preview／prepare／applyと部品復元を保持します。LPC署名を残し、`tools/build_look_layers.py` と署名済み出典パックで再構築できます。

過去21件のフロー確認は改名／状態保持、純prompt、タグ解決、本人隔離、過期編集、自動適用、待機、再試行、取消、新ゲームテンプレート、再利用、代替復元を扱い、モデル／画風版で30件になりました。SD／ネイティブ／画面は隔離またはモックを使い、百科画像は明示したLPCモックで実SD品質は示しません。

## 人物別モデルと画風

既存SD必須九欄に任意の `checkpoint`、`style_lora`、`style_weight`（0–1.5、既定0.8）、`style_trigger`（SFW、1600文字以内）を加えます。IDは現在環境の利用可能なローカル資源です。空のベースモデルは共通継承、空の画風は無効化です。空上書きを正規化で除いて旧指紋／キャッシュを保ち、他人の保存はこの選択を変えません。統一／詳細工房は同じバインドを使います。

選択ベースモデル、人物／衣装／画風LoRA、重み、トリガーを全立ち絵／歩行／CG配合、キャッシュ、素材外見識別情報署名に保持します。変更は新素材を予約します。WebUI／内蔵ComfyUIは人物LoRAなしでも全選択LoRAを適用します。WebUIは要求単位上書きと後復元、ネイティブComfyUIは追加 `style_lora/style_weight` が必要で、欠けると予約前に停止します。存在する未使用衣装／画風重みはゼロにし、節点構造と元ワークフロー／未保存画面は保持します。

モデル／画風版は九件追加（フロー計30件）：四用途独立、永続化、旧キャッシュ一致、変更失効、無効資源／重みの非変更、構造不一致、モックWebUI要求、ネイティブComfyUI対映／事前確認、画風解除重みです。その版に実SD生成や課金要求はありません。

## 複数画風と精修

任意 `style_loras` は最初の画風後に最大七つの順序付き `{lora, weight, trigger, enabled}` を持ちます。重み0–1.5、有効IDは唯一です。無効項目は編集用に残りますが生成へ送りません。ネイティブComfyUIは `style_lora_2/style_weight_2` から `_8` が必要で、未使用の対映はゼロです。内蔵ComfyUIとWebUIは全選択を適用します。

任意 `render_options` はrefiner／hires／adetailerで、各々 `mode` inherit/on/off と `targets` portrait/pixel/cg を持ちます。既定値と空配列を除いて旧キャッシュを保持します。Refinerはローカルベースモデル／切替0.01–0.99、Hiresは拡大器／倍率1–2／Steps1–80／denoise0–1／CFG1–20／サンプラーです。ADetailerは最大四段で実script-info容量内、検出器、信頼度、マスク、サンプラー、prompt、外見識別情報追従、検証済み追加設定を個別指定します。継承と明示無効を区別し、元テンプレート／画面は変えません。

`command` だけの `refresh_sd_capabilities` は接続能力を読み直して保存設定は変えません。WebUIは検出器、script容量、サンプラー、ローカル拡大器、実OpenAPI欄を読みます。不対応／不一致は予約前に停止し、ニューラル拡大器はextras呼び出し前にローカル重みを再確認します。ダウンロードは要求しません。

文字生成はネイティブHires.fixです。参照img2imgはネイティブHires段階がないため、基本解像度で外見識別情報／姿勢を作り、既存拡大器で拡大し、指定倍率／Steps／denoise／CFGで二回目img2imgを行います。ADetailerは最後だけで二重実行せず、未選択段は明示無効にして拡張既定処理を防ぎます。歩行用途は任意、最大2048pxで、両コピー要求に詳細／外見識別情報／制御参照を保持します。

精修欄はWebUI／Forge用です。ComfyUIで明示的on/offを要求すると理由付きで停止し、ネイティブ品質フローを継承する必要があります。無視はしません。複数LoRAは双方で使えます。
